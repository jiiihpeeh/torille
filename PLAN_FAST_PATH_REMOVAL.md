# Removing the lexical supplement from the generic engine

Status: **executed** · `src/expand/fast_path.rs` is deleted.

The 134-row table was reduced to a 44-row closed-spelling table in
`src/expand/closed_spellings.rs`. Everything the generic engine, stem maps,
compound analysis and derivation layer can now name directly was removed; the
residual rows are fused function words (`ennenkuin`, `senjälkeen`, `kuulten`),
a few proper-name/compound reverse-search gaps, and `perehtyneempi`. No row is
a suffix rule or a class paradigm.

The original plan below is kept as the record of the audit and the criteria
used to decide what left the table.

## Why

`src/expand/fast_path.rs` is a hand-maintained `surface -> base` table. It sits
in `check_normal` and `is_known_word` before the stem maps and the engine, and
it accepts surfaces without asking whether the paradigm or the compound
analysis can derive them.

That is the wrong direction for this repository:

- a reported word gets a table row instead of a class/paradigm/compound fix;
- the row helps exactly one surface and silently misses every other member of
  the same class;
- the engine and the supplement can disagree about the base, which changes
  what `check_normal` returns and therefore what `suggest` can offer;
- the table grows without any external authority or coverage check.

The engine must own inflection. `fast_path.rs` may temporarily hold a **closed
function-word spelling** (fused phrases such as `ennenkuin`) or a genuinely
non-generative variant, but it must not hold ordinary inflected forms.

## Current inventory (2026-11-06)

`fast_path.rs` has:

- **134** `ACCEPTED` `(surface, base)` pairs;
- four special-case blocks: `molemmat` (15 surfaces), `pihdit` (1), `selkämä`
  (26), `perehtyneempi` (1).

An engine-only audit (`Engine.inflect(base)`, no fast path) says:

| bucket | count | meaning |
|---|---:|---|
| already generated | **50** | `inflect(base)` already emits the surface; the row is stale |
| base exists, form missing | **59** | the base has a paradigm, but that paradigm does not emit the surface |
| no base in the sanalista | **25** | missing lemma, proper name, derived lexeme, or a surface whose `base` is not a lemma |
| special `selkämä` block | **26** | every surface is already generated by class 10; the block is stale |
| special `molemmat` block | **15** | class `16*H` builds a singular adjective paradigm instead of a plural-only pronoun |
| special `pihdit` block | **1** | class `5*F` builds singular nonsense; its plural partitive is not generated |
| special `perehtyneempi` block | **1** | participle degree; the class-16 degree engine does not reconstruct the positive |

The audit is reproducible; Phase 0 turns it into a committed tool so this table
does not go stale again.

## Work categories

These are the only reasons a surface may still need help after the generic
fixes. Every remaining entry must be assigned to one of them.

### A. Stale rows (delete, no engine work)

The 50 pairs where `inflect(base)` already contains the surface, for example:

```
aivotusten, alastoman, alastomana, alastomia, antimia, elttaantuneen,
enemmittä, harteilleen, hennonnut, hennota, kaarekselle, käräjiä,
lopettamaisillaan, mittaamattomien, nahalla, palpattelisit, parhaan,
parhaat, raamatun, saksia, saksien, saksilla, saksille, saksissa,
saksista, seudui*, suurkaanin, säilikön, tamineita, tapasin, tikas*,
tiuskasi, valjaisiin, vankkurien, viittovan, vällyihin
```

Also delete the `selkämä` block: class 10 already emits all 26 forms.

### B. Defective / plural-only paradigms

Engine work in `src/expand/nominals/utility.rs`, the relevant class module and
`src/expand/nominals/mod.rs`:

- `molemmat` (`16*H`, pronominal quantifier): add a plural-only
  pronoun/nominal mode; do not manufacture `molemmaa`/`molemmatna`.
- `pihdit` (`5*F`): plural-only `-imet` noun; the partitive is `pihtejä`, not
  any of the `pihdid*` shapes.
- `häät` and its possessive/compound forms (`häitä`, `hopeahäihin`,
  `häihimme`): the class engine already handles `bileet`-style `-t` lemmas;
  make the same path reach `häät` and a compound whose head is `häät`.
- `tikasten` (short genitive plural of `tikkaat`): the class already emits the
  `tikkaiden`/`tikkaitten` family; add the `-ten` variant once, for the class.

The existing `plural_only` helper is the model: the class knows the citation
form is plural and the builder omits every singular cell. Extend that helper
instead of adding per-word rows.

### C. Possessive and case forms

These are ordinary case forms plus a possessive, not lexical exceptions:

- `eteemme`, `eteensä`, `haltuunsa`, `ikeniinsä`
- `huostaani`, `huostaansa`
- `ohimennessään`, `poikkimitalleen`, `kävelykierrokselleen`
- `varuillasi`, `keskenämme`

Fix in the same layers that already own possessives:

- `src/expand/nominals/utility.rs` for noun/possessive building;
- `src/expand/derived_forms/` and the adverb tables for fixed adverbs;
- `src/suggest/known/mod.rs` only for the **reverse** direction: it should
  name the base of a form the engine generated, not decide whether the form
  exists.

`huostaani`/`huostaansa` are the postposition `huostaan` plus a possessive;
decide whether a defecting postposition belongs in `grammar/irregular.rs` or
in the closed adverb/postposition table, not in the surface supplement.

### D. Degrees and participles

Add the missing degree rules to the derivation/degree layer
(`src/expand/derived_forms/`, `src/grammar/` and the participle handling in
`src/expand/verbs/`):

- `perehtyneempi` (comparative of the participle `perehtynyt`)
- `edistyneemmät`, `osaavampi`, `siunatumpia`, `sointuvinta`,
  `uupuneemmaksi`
- `hiljempaa`, `loitommalla` (adverb/quantifier degrees)

The rule must reconstruct the positive from the participle/adverb and then
decline the degree; `perehtyneempi` must not be a one-word branch.

### E. Productive derivation

Move these to `src/derivation.rs` / `src/expand/derived_forms/` where the
productive suffix already belongs:

- `-sti` adverbs: `kehottavasti`, `kehoittavasti`, `käskevästi`,
  `paheksuvasti`, `rauhoittavasti`, `suojelevasti`, `sisäkohtaisesti`,
  `koneentapaisesti`
- agent/quality nouns: `liinaompelijatar`, `pormestarinna`, `nyrpistyksessä`,
  `unhotusta`, `nuhteellista`
- participle-derived adjectives/nominals: `mustuneeseen`, `rusoittava`

Some of these bases are missing from the sanalista (see G). Add the lemma or
fix the class first; do not add a suffix branch to `is_known_word`.

### F. Compound analysis

These are compounds whose head or modifier is an inflected form. Fix
`expand::compound_head_forms`, `src/compound.rs` and the bounded splitter in
`src/suggest/known/compound.rs`:

- `morsiuslahja`, `morsiusneidot`, `morsiustyynyt`
- `pariisilaismuodin`, `rihvelitaulu`
- `simasuu`, `tienpuoleen`, `ventovieraita`
- `yhtäkaikki`, `koneentapaisesti`
- `liinaompelijatar`, `kävelykierrokselleen`

The rule is already “modifier may be a known inflected form, a combining form
or a bound prefix, and the whole word inflects as its head”. Extend that
predicate where it cannot reach these heads; keep the resulting base equal to
the head lemma.

### G. Data and proper-name gaps

Some rows are not engine bugs at all. Add the missing source data or remove the
row after authority checks:

- missing lemmas / derived lexemes: `kehoittaa`, `kinkeri`, `ompelijatar`,
  `mustunut`, `nyrpistys`, `paheksuva`, `rusoittaa`, `sisäkohtainen`,
  `suojeleva`, `unhotus`, `käskevä`
- proper names: `hokasien`/`honkasien` (from `Hokkanen`/`Honkanen`),
  `selmallakaan` (`Selma` + `-kaan`)
- postpositions/adverbs not in the sanalista: `kuulten` and its possessives

Use Kotus first, then Wiktionary as the higher authority for the form decision
(per repository policy). If the word is not real, delete the row and add a test
that it stays unknown. Regenerate the noun/verb oracles, stem maps, `all_forms`
and the derived blobs after any sanalista/class change.

### H. Closed function-word spellings and genuine variants

A small number of surfaces cannot be derived by morphology because they are
fused phrases or accepted spelling variants. They should leave `fast_path.rs`
and live in a deliberately named, data-backed module, for example
`src/expand/closed_spellings.rs` + `data/closed_spellings.csv`:

- fused phrases: `aivankuin`, `ennenkuin`, `niinkuin`, `niinkauan`,
  `silloinkun`, `senjälkeen`, `sentähden`, `minkätähden`
- fused conjunction/negation: `vaikken`, `itsekunkin`
- fixed adverbial spellings: `edeltäkäsin`, `alhaaltapäin`,
  `ylhäältäpäin`, `äkkipikaa`, `yllinkyllin`, `kuulten` family
- accepted older/alternative spellings: `tynnyrineen`, `hennonut`,
  `tikasten` if Wiktionary confirms it

Rules for this module:

1. Every row is an **exact surface**, never a suffix or a prefix.
2. The file has a comment/source for each row and a test that the engine still
   does not derive it generically; if the engine later learns it, the row
   fails the test and is deleted.
3. The module is called only after the engine/stem-map gates; it cannot shadow
   a regular paradigm base.
4. It is not a spelling-correction table and does not feed suggestions except
   through the normal `plain` policy.

### I. Typos and non-words (delete)

Verify these against Wiktionary before doing any work. If they are typos, remove
the row and pin the rejection test:

- `avainkuin` (likely `aivankuin`)
- `ylhäätäpäin` (likely `ylhäältäpäin`)
- `ninkälaisia` (dialect/typo; standard `minkälaisia`)
- any other row whose only attestation is the original report

Do not “fix” a typo by teaching the engine to generate it.

## Delivery phases

### Phase 0 — Make the supplement auditable

- [ ] Add `tools/src/bin/audit_fast_path.rs` (or a Python tool) that parses
      `fast_path.rs`, calls the engine for each base, and prints:
      `surface`, `base`, `generated` / `missing` / `no-base`, plus the special
      blocks.
- [ ] Add a feature or test-only switch that disables the `fast_path` calls in
      `check_normal.rs` and `suggest/known/mod.rs`, so a test can prove a
      surface is recognised by the engine/stem maps alone.
- [ ] Record the baseline: `check_normal_fast` and `check_normal` outcomes for
      every surface, and the current `check_fast` benchmark.
- [ ] Add a golden list of the surfaces (test data, not production) so every
      later phase can assert the base it returns.

**Exit:** the audit tool reproduces the inventory above and the baseline test
runs in CI.

### Phase 1 — Delete the stale rows

- [ ] Delete the 50 engine-generated `ACCEPTED` pairs.
- [ ] Delete the `selkämä` special block.
- [ ] Re-run the audit: no remaining row may be engine-generated.
- [ ] Run the golden list: every surface still resolves to the same base.

**Exit:** a smaller table and no engine changes; the easiest review in the
whole plan.

### Phase 2 — Fix the engine-owned paradigms

Work in this order so each fix removes rows instead of adding them:

- [ ] `molemmat` plural-only pronoun (`16*H`).
- [ ] `pihdit` plural-only `-imet` noun (`5*F`).
- [ ] `häät` and its possessives/compound forms.
- [ ] `-ten` genitive plural variant (`tikasten`, `kuningasten`).
- [ ] Possessive/case forms in C.
- [ ] Adverb/participle degrees in D.

Each class fix gets a test on the class, not on the reported word alone. The
golden list may only shrink.

**Exit:** B/C/D rows are gone; `inflect(base)` emits every surface that the row
used to supply.

### Phase 3 — Fix productive derivation and compound analysis

- [ ] Derivation cases in E, one suffix family at a time.
- [ ] Compound cases in F, with `compound_head_forms` /
      `detect_compound` tests.
- [ ] Add data/proper-name rows from G and regenerate the affected maps.

**Exit:** E/F/G rows are gone or reduced to true data gaps; the strict
comparison reports no lost forms.

### Phase 4 — Move the genuine closed spellings out

- [ ] Create the closed-spelling module and its CSV.
- [ ] Move H rows; delete I rows after Wiktionary checks.
- [ ] Change `check_normal` and `is_known_word` to call the new module.
- [ ] Delete `src/expand/fast_path.rs`, `pub mod fast_path;` and every import.
- [ ] Update `AGENTS.md`, `TODO_fast_detection.md` and the performance notes.

**Exit:** `fast_path.rs` is gone. The only non-engine surfaces left are exact,
documented closed spellings.

## Guardrails

- No new `fast_path.rs` row after Phase 0 unless it is a closed spelling in
  the new module, with a source and a failing test that the engine cannot
  derive it.
- Never add a suffix rule to `is_known_word` for one of these words; the
  existing AGENTS rule applies unchanged.
- Every class/compound fix must be tested against the whole class or the
  compound family, not just the reported surface.
- The final state is measured against Wiktionary/Omorfi/Voikko. A row that
  only the report attests is a typo candidate, not an engine requirement.
