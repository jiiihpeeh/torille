# DATA_CLEANUP_PLAN — tidying `data/`

Plan for removing redundant local artifacts and documenting what stays. The
goal is that `git ls-files data` contains only files the build, the harness or
the license needs, and that everything else is either regenerable or gone.

Baseline measured 2026-11-05: `data/` is **12 GB**; 22 files are tracked
(~23 MB) and 14 are ignored local artifacts (~12 GB).

Nothing here deletes a tracked file until its replacement or provenance is
settled. The build, the Python harness and the comparison gate are run after
each phase.

## Decisions needed

1. Keep the two live oracle databases (6.2 GB) or delete and rebuild on
   demand? **Recommend keep one each**, because they are the only local
   source for refreshing the frozen reference tables.
2. Delete the Wiktionary dump/index/db (776 MB)? **Recommend yes**; they are
   refetchable and only feed exploratory tools.
3. Delete `tags_layout.json` and `test_experimental_features.py`? **Recommend
   yes**; both depend on the removed reranker.
4. Keep `wiktionary_finnish_morph.jsonl` as a 2-row fixture, or let the
   fetcher own it (and ignore it)? **Recommend ignore it** and commit a
   fixture only if a test needs one.
5. Split `data/` into `source/`, `reference/`, `generated/`? **Recommend no**
   for the release: it would churn `build.rs`, `include_bytes!`, the tools and
   the docs for no functional gain. Do it later if the flat directory keeps
   growing.
