# Building the torille Firefox add-on from source

This document describes how to build the submitted Firefox extension
(`torille`, version 0.5.0) from the accompanying source archive. The result
is the same code that is packaged in `torille-firefox.xpi`.

## Tested build environment

The release artefacts were built on:

| Component | Version / platform |
|---|---|
| OS | Ubuntu 26.04.1 LTS, Linux x86_64 |
| Rust | rustc 1.99.0, cargo 1.99.0 |
| wasm-pack | 0.15.1 |
| wasm-opt (Binaryen) | 133 |
| Node.js | v22.14.0 |
| npm | 11.12.1 |
| zip (Info-ZIP) | 3.0 |
| Python | not required for the add-on build |

The build should also work on macOS and on Windows through WSL2. Linux x86_64
is the tested configuration.

### Installing the requirements

Rust (via rustup):

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustup target add wasm32-unknown-unknown
```

wasm-pack 0.15.1:

```bash
cargo install wasm-pack --version 0.15.1 --locked
```

Binaryen (`wasm-opt`) 133: install the release for your platform from
<https://github.com/WebAssembly/binaryen/releases> and make sure `wasm-opt`
is on `PATH`. On Debian/Ubuntu, `apt install binaryen` may provide an older
version; wasm-pack still works, but the submitted binary was optimized with
133.

Node.js 22.14.0 and npm 11.12.1: install Node 22 with your package manager or
with nvm, then check:

```bash
node --version   # v22.14.0
npm --version    # 11.12.1
```

Build tools:

```bash
sudo apt install build-essential zip
```

`npm ci` downloads the JavaScript build dependencies from the npm registry.
`cargo`/`wasm-pack` download the Rust crates from crates.io. Those are
open-source third-party libraries and are not included in the source archive.

## One-command build

From the root of the source archive:

```bash
chmod +x build-firefox-addon.sh
./build-firefox-addon.sh
```

The script performs every step, including the engine build, the wasm build,
the dependency install and the add-on packaging. It sets
`TORILLE_NO_FETCH=1` because the required generated `maps/*.bin.gz` data files
are included in this source archive; the normal first build would otherwise
fetch them from the project's `maps` branch.

Output:

```text
extensions/firefox/dist/                 loadable unpacked add-on
extensions/firefox/torille-firefox.xpi  packaged add-on
```

## Manual build steps

The same steps the script runs:

```bash
# 1. Build the Rust engine.
cargo build --release -p torille

# 2. Compile the engine to WebAssembly and generate torille-wasm/pkg/.
(cd torille-wasm && wasm-pack build --release)

# 3. Install the extension's JavaScript build dependencies.
(cd extensions/firefox && npm ci)

# 4. Compile TypeScript, bundle the Solid options page, copy the wasm, zip.
(cd extensions/firefox && npm run build)
```

`npm run build` runs `tsc` and `extensions/firefox/build.mjs`. The latter
bundles `src/content/content.ts` with esbuild (content scripts cannot use ES
module imports), bundles the Solid settings page, copies
`torille-wasm/pkg/torille_wasm_bg.{js,wasm}` into the package, and writes the
`.xpi`.

## Verifying the result

Load the unpacked extension:

1. Open `about:debugging#/runtime/this-firefox`.
2. Choose **Load Temporary Add-on…**.
3. Select `extensions/firefox/dist/manifest.json`.
4. Open a page with a textarea and type `talo taloo koirra`.
   `taloo` and `koirra` should be underlined; clicking one should open the
   suggestion dropdown.

The packaged add-on can also be opened directly from
`extensions/firefox/torille-firefox.xpi`.

## What is in this source archive

Included:

- Rust engine source (`src/`, `build/`, `Cargo.toml`, `Cargo.lock`)
- Rust wasm bindings (`torille-wasm/`)
- TypeScript/TSX extension source (`extensions/firefox/src/`)
- Build scripts (`build-firefox-addon.sh`, `extensions/firefox/build.mjs`)
- Committed Kotus CSV data and generated binary maps needed by the build
  (`data/`, `maps/*.bin.gz`)
- npm lockfile and TypeScript configuration

Excluded intentionally (machine-generated or third-party):

- `target/` (Rust build output)
- `torille-wasm/pkg/` (generated by `wasm-pack`)
- `extensions/*/node_modules/`, `torille-wasm/demo/node_modules/`
- `extensions/*/dist/`, `torille-wasm/demo/dist/`
- packaged `.xpi`/`.zip` files
- `.git/`

The submitted JavaScript is generated from the included TypeScript by
`tsc`/esbuild, and the submitted wasm is generated from the included Rust by
`wasm-pack`. No source file is minified. The generated Rust noun-class modules
under `src/expand/nominals/` are committed source generated from the included
`rules/` data and generator under `tools/oracle/`; they are kept in the archive
so the build is byte-for-byte reproducible from this source snapshot.
