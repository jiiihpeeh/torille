This is the implementation-level plan for the cold morphology resolver behind
the grammar and style layers. The parent plan owns the targets and the
exact-output gate; this document names the code changes, their order, and the
measurements that decide whether a phase landed.

“Cold” here means **the per-document `MorphologyCache` is empty**, not CPU
cache coldness. A cold miss is a lexicon search; a warm hit is one
`HashMap<String, Arc<WordInfo>>` probe. The work is to make the first search
cheap and to stop the grammar/style path paying for searches it does not need.

## 2. Where the cold seconds go

A cold miss runs this path:

```
analyze_morphology                          src/morphology/mod.rs:274
  └─ cache.resolve                          :203
       └─ resolve_word                      :348
            ├─ resolve_word_fast            :431
            │    direct sanalista row
            │    → add_forms_from_lemma → inflect_all(..., possessives=true)   :1053
            │    noun/verb stem map
            │    → add_readings_from_base_matched → inflect_all(...)           :1100
            │    fast clitic/possessive host
            └─ resolve_word_slow            :730
                 └─ find_bases_for_analysis src/expand/find_bases.rs:232
                      heads+tails → head-1 (cap 3000) → prefix-3 → prefix-2
                      → short-lemma scan → clitic
                      each candidate: lemma_emit → emits_form   (cached probe)
                 winner → add_forms_from_lemma → inflect_all     (uncached)
```

### 2.1 The search keeps walking

`find_bases_for_analysis` passes `keep_walking_with_direct = has_direct`
(`find_bases.rs:246`) so a homonym behind a direct lemma is not lost: `lasta`
is both a splinter lemma and the partitive of `lapsi`. A common word that is
already a direct lemma therefore still runs the head/tail, head-1 (up to 3,000
lemmas), prefix-3, prefix-2 and short-lemma phases. The parent plan measured
281 candidates for `kanssa` (~726 ms), 278 for `liika` (~4.3 s) and 163 for
`talossa` (~118 ms).

### 2.2 Every candidate is verified by building a paradigm

`lemma_emit` → `emits_form` (`src/expand/mod.rs:582`) builds the lemma's form
set on the first probe and caches it under a key of `(lemma, inflections, pos,
possessives, lexicon)`. The cache makes repeated probes of the same base cheap,
but the first probe of each base is a full inflection. The cache is capped at
100,000 words and cleared wholesale when full (`:606`).

### 2.3 Reading extraction builds the paradigm a second time

`add_forms_from_lemma` and `add_readings_from_base_impl` call
`inflect_all(..., possessives=true)` and then keep only the form whose surface
matches. `inflect_all` (`src/expand/mod.rs:489`) lists the whole paradigm and
deduplicates it with a `HashSet<(String, Confidence, Vec<Tags>)>`, cloning
every word and reading. This path is **not** served by `emits_form`'s cache and
repeats for every surface of the same base.

### 2.4 Ambiguous partitive plurals skip the cheap path

`needs_full_base_search` (`src/morphology/mod.rs:721`) sends surfaces ending in
`-ja/-jä`, `-ia/-iä`, `-ita/-itä`, `-uja/-yjä`, `-oja/-öjä`, `-eja/-ejä` to the
full recognition walk, because the stem map names one base and a second base
can change a correction (`kirjoja` = `kirja`/`kirjo`). `arvoja` costs ~50 ms
for this reason.

### 2.5 Clitic hosts repeat the full word search

`resolve_word` tries `strip_all_clitics` and `strip_possessive` only when the
host resolves through `resolve_word_fast`. If the host is not cheap, the slow
walk runs on the *whole* surface instead of the host. `palajakaan` hosts
`palaja`; the host is not a lemma, so the resolver walks `palajakaan` and pays
777 ms.

### 2.6 Unknown words exhaust the ladder

A name, dialect form or archaic spelling never finds a base; it runs every
phase before returning empty. Those are the 0.2–0.8 s words above. The parent
plan’s long tail (`kenoveeva*`, `kulettivat`, `saraseenit`) is this case.

## 3. Goals

- Full 1,959-word page: **≤ 3 s cold, single-thread** (from 22.6 s).
- 96-word slice: **≤ 250 ms cold** (from 560.7 ms).
- Keep the 20-word slice at **≤ 100 ms**.
- Slow tail: every word in the measured top-20 **≤ 20 ms** (from 0.35–0.78 s).
- Warm path unchanged or better: morphology **≤ 1 ms**, all layers **≤ 25 ms**.
- No diagnostic, correction or acceptance change. The exact-output fixtures
  are byte-identical.

Secondary (same primitives, not the acceptance target): reduce the suggestion
path’s candidate population and the fast path’s `mesaanipurjeineen`-class tail.

## 4. Non-goals

- **Do not remove archaic or rare forms.** The `-in` genitive plural, `-sten`,
  `-nna` feminines and `kuulten` stay accepted and non-suggested. They are not
  a hot-path cost (they are outside the fast form subset and the suggestion
  set); removing them would make those inputs slower, not faster.
- Do not ship a full form→lemma reverse index. The parent plan’s §4.5 decision
  gate still applies (95% coverage, ≤3 MB compressed).
- Do not add suffix lists. Use morphology: stem + legal ending + gradation.
- Do not change `check_normal_fast`’s acceptance or the grammar/style
  diagnostics as a side effect.
- Do not optimise the warm rule pass in this plan beyond the cache/allocation
  items in Phase 6; the parent plan owns the ≤5 ms rule target.

## 5. Invariants

- The `MorphologyCache` stays per `TextAreaState`, capped at 4,096 words, with
  one `Arc<WordInfo>` per surface and no per-token clone on a hit.
- `TORILLE_SINGLE_THREAD=1` still produces the wasm shape.
- A shallow result may be less complete, never wrong for the rule that asked.
  Rules that need ambiguity request a deep upgrade; false negatives are
  preferred over false positives.
- `emits_form` remains a conservative probe: a `false` means “this lemma cannot
  emit the surface”, never “I did not look”.
- The stem-shape filter is conservative: a zero bit only skips a candidate; a
  one bit takes the old path. Every real form must pass.
- The exact-output fixtures (`tests/fixtures/syntax_diagnostics.json`,
  `tests/fixtures/style_diagnostics.json`) and the syntax/style eval suites are
  the correctness gate for every phase.

## 6. Design overview

The target shape is a **ladder plus a deep upgrade**, not one uniform walk:

```
shallow (default)                         deep (on demand)
-----------------                         -----------------
1 direct lemma                            8 head-1 walk
2 stem map (noun/verb)                    9 prefix-3 / prefix-2
3 closed spelling                        10 short-lemma scan
4 clitic host (reuse host WordInfo)      11 clitic phase on the host
5 possessive host (reuse host WordInfo)
6 compound (modifier + head)
7 head/tail phase 1 + stem-shape filter
```

Two shared primitives make the ladder cheap:

- **`form_readings(base, surface)`** — walk the engine and return only the
  matching form’s readings, without listing and deduplicating the paradigm.
  This replaces the uncached `inflect_all` in reading extraction.
- **`lemma_might_emit(lemma, surface)`** — the build-time stem-shape mask. It
  rejects a candidate before `emits_form` builds its form set.

The `MorphologyCache` records `Depth` per entry (`Direct`, `StemMap`,
`HeadsTails`, `Prefix`, `Clitic`, `Possessive`, `Compound`, `Unknown`) so the
harness can show which rung resolved a page and which words still fell through.

## 7. Phases

Each phase is independently shippable. The order is by risk and dependency,
not by the parent plan’s §4 numbering: the no-semantic-change wins land first,
the shallow/deep split lands last because it is the only phase that changes
what the first pass computes.

### Phase 0 — pin the baseline and add depth counters (0.5 day)

- Extend `CacheStats` with per-`Depth` counts and `slow_resolutions`; count on
  insert and on `resolve_deep` only, so the warm hit path does not change.
- Add the fields to `perf_grammar_style --json` and print a small depth table
  in the text output.
- Record the §1 baseline in this file. A machine-local copy may go to
  `reports/cold-search-baseline.json` (gitignored) for the regression gate.

**Acceptance:** the tool runs on a clean checkout, the numbers reproduce §1
within noise, and no diagnostic changes.

### Phase 1 — targeted reading extraction (1–2 days)

**Change.** Refactor the engine walk behind `inflect_all` into one visitor and
add `form_readings`:

```rust
// src/expand/mod.rs
pub fn form_readings(
    lemma: &str,
    inflections: &[Inflection],
    cat: &Catalogues,
    lexicon: Option<&LexiconIndex>,
    pos: PartOfSpeech,
    possessives: bool,
    surface: &str,
) -> Option<Vec<Tags>>;
```

It walks the same sources as `inflect_all` (class engines, `degree_forms`,
`numeral_forms`, `compound_head_forms` for a classless lemma), keeps only forms
whose word equals `surface`, and deduplicates with `tags::add_reading` instead
of cloning every form into a `HashSet`. `inflect_all`, `emits_form` and
`form_readings` share the walk so the three cannot drift.

Use it in `add_forms_from_lemma` and `add_readings_from_base_impl`. Pass
`possessives` only when the surface actually carries a possessive or clitic
(the host path already strips those before calling the fast resolver); add a
small `surface_has_possessive` helper next to `strip_possessive`.

**Tests.**

- `form_readings` agrees with `inflect_all(...).iter().find(|f| f.word == surface)`
  on a fixture covering a noun, an adjective degree, a numeral, a verb, a
  classless compound and a possessive form.
- Multiple readings of the same surface are all kept; duplicate readings are
  not.
- The existing `expand::tests::emits_form_agrees_with_inflect_all` stays green.

**Acceptance:** 96-word cold ≤ 450 ms; full page ≥ 10% faster; exact-output
fixtures unchanged.

**Risk:** a multi-class or multi-reading form loses a reading. Mitigation: the
agreement test is exhaustive over the fixture, not a spot check.

### Phase 2 — reuse the clitic/possessive host (1 day)

**Change.** In `resolve_word`, strip clitics and possessives **before** the
slow walk, always. Resolve the host through the shallow ladder; if it resolves,
copy its `WordInfo`, add the clitic/possessive tag to every reading, set
`Depth::Clitic`/`Depth::Possessive`, and cache the full surface. Resolve the
host once and let the host key in `MorphologyCache` serve the other clitic
variants (`palajakaan`, `palajankin`).

Keep the current fast-host path as the first branch; this phase extends it to
hosts that need the slow ladder instead of running the slow walk on the full
surface.

**Tests.**

- `palajakaan`, `palajankin`, `silloinkin`, `kanssasi`, `monineen`, `taloni`,
  `talossanikin`: the readings and the clitic/possessive fields match the
  current resolver.
- A clitic on a word that is itself a lemma (`kokin` must stay `kokki`, not
  `ko` + `kin`).
- Exact-output fixtures unchanged.

**Acceptance:** `palajakaan` ≤ 5 ms (from 777 ms); `silloinkin` and `kanssasi`
≤ 5 ms; no diagnostic change.

**Risk:** a clitic that changes the host’s morphology. The existing
`strip_all_clitics` order is the authority; do not invent a new parser.

### Phase 3 — multi-base ambiguous partitives (1–2 days)

**Change.** Replace the `needs_full_base_search` full walk with a multi-base
stem-map query:

```rust
// src/suggest/known/stems.rs or the stem-map API
pub(crate) fn find_bases_via_stem_map(surface: &str, pos: PartOfSpeech) -> Vec<&'static str>;
```

Resolve every named base with `form_readings`/`emits_form`, collect the
readings of the bases that actually emit the surface, and return a shallow
`WordInfo` with all of them. Keep the full walk as the fallback when the stem
map names nothing or the bases disagree in a way the rule pass cannot use.
`kirjoja` must still be both `kirja` and `kirjo`; `arvoja` must resolve from
`arvo` without the head-1 walk.

**Tests.**

- `kirjoja`, `arvoja`, `taloja`, `kouluja`, `vesiä`: the base set and readings
  match the current full-walk result.
- A word the stem map cannot name still falls through to the full walk.
- Exact-output fixtures unchanged.

**Acceptance:** `arvoja` ≤ 2 ms (from ~50 ms); full page ≥ 15% faster than
Phase 2; no diagnostic change.

**Risk:** the stem map’s value list is incomplete for some classes. The
fallback and the comparison test are the guard.

### Phase 4 — lemma stem-shape filter (3–4 days)

**Change.** Build a conservative per-lemma mask of stem prefixes at build time
and use it to reject candidates before `emits_form`.

- New generator `tools/src/bin/gen_lemma_stem_shapes.rs`, same engine-driven
  pattern as `gen_derived`: inflect every classed lemma with `inflect_all`
  (noun reading, possessives on), hash the first four characters of every
  emitted form, and set the bit. No ending inventory is needed: the form's
  prefix is the stem's own prefix for any stem of four or more characters,
  and a shorter form stores its whole surface. Classless rows get an all-ones
  mask (the filter never rejects them).
- New blob `maps/lemma_stem_shape.bin.gz`: 104,774 rows × 8 bytes = 838 KB
  raw, 75 KB gzip. `build.rs` includes it; the generator is rerun after a
  `RULES`/sanalista change and the blob is published on the `maps` branch.
  When it is absent, `build.rs` writes an empty header and the filter is
  disabled.
- Runtime probe `src/expand/stem_shape.rs::might_emit(lemma, surface)`: hash
  the surface's first four characters and test the lemma's mask. Called from
  `lemma_emit`, which covers `find_any_base_with` and the recognition-only
  `find_bases_with_inner` paths. It does **not** touch `check_normal_fast`'s
  cheap gates or the suggestion path's neighbour/form collection.

**Tests.**

- Every form of every lemma in `tests/fixtures/noun_classes.txt` passes
  `might_emit` (`the_mask_accepts_the_noun_fixture`).
- A stratified sample of the lexicon (every 97th row) passes
  (`the_mask_accepts_real_forms`).
- The generator spot-checks every 97th lemma's forms against `emits_form`
  before writing the blob.
- The filter is a no-op when the mask is all ones or the blob is absent.

**Acceptance:** candidate scans on the top-20 slow words drop ≥ 50%; 96-word
cold ≤ 300 ms; full page ≤ 10 s; no diagnostic change.

**Risk:** a real form is rejected because its prefix was not in the generated
mask. Mitigation: the generator hashes every form `inflect_all` emits; a
classless row is all-ones; the fixture and stratified tests check the runtime
hash and row lookup; a false positive only costs one `emits_form`.

### Phase 5 — shallow/deep split and the ladder (4–6 days)

**Change.** Make the first pass shallow; keep the deep walk for explicit
upgrades.

- `MorphologyCache::resolve` is the shallow ladder: direct lemma, multi-base
  stem map (ambiguous partitives), negation and connegative tables,
  clitic/possessive host, compound. It never calls `resolve_word_slow`.
- `MorphologyCache::resolve_deep` remains. `analyze_morphology` uses it only
  for the numeral-governed partitive (`kaksi lasta`); the exact-output
  fixtures pass without a generic per-rule upgrade hook, so none was added.
- `resolve_word_fast` collects every base for an ambiguous partitive
  (`collect_bases_via_stem_map` and the verb counterpart), so `kirjoja` keeps
  `kirja` and `kirjo`, and `pieniä` keeps the adjective and the verb.
- A word the ladder cannot name stays `Depth::Unknown`. A rule that later
  needs the head/tail ambiguity can call `resolve_deep` for that token; the
  shallow entry is upgraded in place and cached.

**Tests.**

- Exact-output fixtures byte-identical.
- `lasta`/`lapsi`: shallow `lasta`; `kaksi lasta` upgrades and gains the
  partitive (`a_numeral_upgrades_the_partitive_homonym`).
- `tuli` noun/verb (`a_direct_lemma_keeps_the_hidden_verb_reading`) and
  `kuusi` tree/numeral (`kuusi_keeps_the_tree_and_numeral_readings`).
- 20-, 96- and 1,959-word fixtures; all existing syntax/style eval suites.

**Acceptance:** ≥ 95% of page tokens resolve without the head-1 walk; 96-word
cold ≤ 250 ms; full page ≤ 3 s single-thread; 20-word stays ≤ 100 ms;
diagnostics unchanged.

**Landed:** 0 head/tail resolutions, 96 words 163.6 ms, full page 2.71 s
single-thread, 20 words 79.6 ms, fixtures unchanged.

**Risk:** a rule silently loses a reading and a diagnostic. Mitigation: the
fixture diff is the gate; the numeral upgrade covers the one case the
fixtures needed; prefer a false negative over a false positive, as everywhere
else.

### Phase 6 — cache and allocation hygiene (2 days, secondary)

**Change.** These do not affect the cold search but keep the warm path and the
process-level caches healthy after the earlier phases.

- Give `emits_form`’s paradigm cache a two-generation eviction instead of
  clearing wholesale; expose `hits`/`misses`/`words` for the harness.
- Give `MorphologyCache` the same two-generation eviction; keep the 4,096 cap.
- Remove per-token allocations in the warm rule pass: `degree_base`,
  `attribute_shape`, `head_shape`, `nominal_case`; return the cached
  `Arc<WordInfo>` everywhere (no clone of readings or lemma strings).

**Acceptance:** warm morphology ≤ 1 ms; warm all ≤ 25 ms (stretch ≤ 15 ms);
no diagnostic change. The parent plan’s ≤5 ms rule target remains its own
Phase 3.

### Phase 7 — wasm verification (2–3 days, only if the target is not met)

- Re-run the browser probes (`probe-timing.mjs`, `probe-toggle.mjs`) and the
  wasm size report. The stem-shape blob must stay within the ≤ +1 MB budget.
- If the cold page is still above 500 ms after Phase 5, add sentence chunking
  with progress and cancellation (parent plan Phase 5). The target is no
  uninterrupted worker task over 50 ms.
- The reader stays spelling-only until the 500 ms or progress gate is met.

```bash
target/release/perf_grammar_style --words 20  --repeat 3 --single-thread --json
target/release/perf_grammar_style --words 100 --repeat 3 --single-thread --json
target/release/perf_grammar_style --words 2000 --repeat 1 --single-thread --json

  --tokens 2000 --single-thread --json
```

Rules:

- `--single-thread` is the acceptance shape; the wasm has one thread. The
  multi-thread number is informative only.
- Run the release profile. Debug numbers are meaningless.
- Record a machine-local baseline in `reports/cold-search-baseline.json`; the
  regression gate fails on a 2× regression, not on absolute milliseconds.
- Add a `cold_by_depth` table to the JSON so a phase that moves words from
  `HeadsTails` to `StemMap`/`Direct` is visible even when the wall time is
  noisy.

## 9. Risks and rollback

| risk | guard | rollback |
|---|---|---|
| a phase changes a diagnostic | exact-output fixtures + eval suites | revert the phase; do not update the fixture as a side effect |
| shallow resolution loses a needed homonym | `lasta`/`lapsi` test; fixture diff; prefer false negatives | keep the rule on deep and document it |
| the stem-shape filter rejects a real form | exhaustive catalogue/all-forms recall test; classless all-ones | disable the filter with a one-line switch and re-measure |
| the stem-shape blob grows the wasm | ≤ +1 MB gate; 838 KB raw target | ship the filter native-only, keep the wasm on the old path |
| the multi-base stem map changes a correction | comparison test against the full-walk result | fall back to `needs_full_base_search` for that suffix |
| clitic-host reuse changes the reading | existing clitic tests + fixture diff | keep the current fast-host path and skip the slow host |
| the cache grows without bound | `CacheStats`, cap, two-generation eviction | drop to clear-on-cap (current behaviour) |
| a phase helps the host but not the wasm | always re-measure with `--single-thread` | do not claim the phase landed on a multi-thread number |

## 10. Open decisions

1. **Readings cache vs targeted walk.** Phase 1 starts with a targeted walk.
   If the same verb base’s many surfaces dominate after Phase 4, add a small
   readings map to `emits_form`’s cache (keyed like the form set, capped, two
   generations). Do not add it speculatively; the wasm budget is tight.
2. **Ending inventory for `lemma_might_emit`.** Reuse `tools/src/stem_key.rs`’s
   noun/verb ending lists rather than adding a second inventory. If the
   runtime cannot share the tool code, generate the mask with a superset of
   endings and fall back to `true` on an unknown ending.
3. **Deep-upgrade API.** Prefer an explicit `analyze_syntax_with_cache` hook
   over a hidden global cache. The hook makes the cost visible and testable.
4. **Where the stem-shape filter ships.** Native first; wasm only if the
   compressed blob stays within the parent plan’s ≤ +1 MB budget.
