# tools

Development, verification and corpus-building tools for `torille`. Nothing in
this directory is part of the shipped library; the tools exist to exercise the
engine and to compare it against Omorfi and Voikko.

**License:** the tools are `MIT OR Apache-2.0`, except for the files that are
tied to Omorfi or Voikko. Those are `GPL-3.0-or-later`, because Omorfi is
GPLv3 and libvoikko is GPLv2-or-later. The complete GPL text is in
[`LICENSE-GPL-3.0`](LICENSE-GPL-3.0).


## Layout

### Rust drivers (`src/bin/`)

The `torille-tools` crate exposes the engine on the command line. Build all
binaries with:

```bash
cargo build --release -p torille-tools
```

Everyday probes:

| binary | purpose |
|---|---|
| `inflect` | inflect a lemma and print every generated form with its reading |
| `lookup` | build the reverse index and answer "what is this word a form of?" |
| `check` | check a word, with the full compound-aware path |
| `check_normal` | the per-keystroke gate the wasm demo uses |
| `hyphenate` | show permitted Finnish line breaks, with `--json` offsets |
| `look_base` | show the bases and generated forms for one word |
| `derive` | derivational forms of a base word |
| `lookup_recall` | score lookup against `(form, lemma)` pairs on stdin |
| `suggest_correct` | print ranked suggestions for a misspelling |

Corpus and code generation:

| binary | purpose |
|---|---|
| `build_catalogue` | refine the catalogue CSV from the engine's own output |
| `train_data` | build the corruption/inflection training splits |
| `rerank_data` | build contrastive reranker candidates from the training splits |
| `tags_dump` | emit the `Tags` layout used by the Python trainer |

Profiling and one-off probes:

| binary | purpose |
|---|---|
| `rerank` | the production reranker path, end to end |
| `rerank_bench` | per-stage reranker latency |
| `profile_hot` | phase timings for the per-keystroke path |
| `probe_koirissa` | reproduce the `koirissa` / `korissa` candidate-pruning case |

### Python harness

The Python files are the external-verification harness. The gates and their
baselines are documented in [`../docs/harness.md`](../docs/harness.md); the
entry points are:

```bash
python3 tools/check_word_against_omorfi.py kissa
python3 tools/report_by_class.py --split reports/classes
python3 tools/summarize_class_report.py reports/noun-classes.json
python3 tools/show_illegals.py --summary
python3 tools/show_illegals.py --no-refresh reports/noun-classes.json
python3 tools/show_illegals.py --refresh
python3 tools/test_binding_agrees_with_binary.py
python3 tools/test_reverse_lookup_recall.py
python3 tools/test_experimental_features.py
```

`show_illegals.py` fingerprints the engine, data, harness and installed binding
and refreshes the class report only when that fingerprint or the report's
parameters changed; `--refresh` / `--no-refresh` override the decision. Its
refresh uses `data/kotus_nomines.sqlite` as the noun oracle by default; `--live`
uses live Omorfi+Voikko.

The remaining scripts fall into four groups:

- **Lexicon builders** — `build_*`, `add_*`, `apply_all_derivations.py`,
  `extract_class_rules.py`. `build_nomine_lexicon.py` and
  `build_verb_lexicon.py` now include the engine enrichment, the comitative and
  negative-mood verb cells, and the connectives/connegatives tables that used
  to be separate update/fill scripts.
- **Generated tables** — `build_stem_to_base_map.py --source
  engine|hybrid|oracle` and `build_all_forms_csv.py --source engine|oracle`.
  `engine` (the default for both) asks the current binding, so a fixed
  inflection bug cannot leave its old invented forms in a checked-in blob.
  `hybrid` keeps oracle rows only where the current engine still produces
  them, plus the combining forms of numerals/pronouns and classless compound
  heads.
- **Audits and reports** — `audit_*`, `walk_check.py`, `fingerprint_nouns.py`,
  `compound_recall.py`, `classify_lemma.py`, `report_by_class.py`,
  `show_illegals.py`.
- **Diagnostics** — `diag_*.py`, `csvtool.py`, `run_wordlist.py`,
  `make_*.py`, `omorfi_harness.py`, `check_hyphenation_against_voikko.py`.
- **Corpus fetches** — `fetch_wiktionary.py`, `fetch_finnish_books.py`,
  `rebuild_book_catalog.py`.

### Training

`train/` is pure-numpy reranker training and evaluation. It reads the JSONL
corpora under `data/rerank*` and writes reports under `data/rerank_v2*/`.
`parallel_rerank.py` and `post_rerank.py` orchestrate the sharded runs.

*Note:* the training corpus generation is expensive and the full
`data/train/train.jsonl` is much larger than the committed `data/rerank/`
split. When regenerating the committed corpus, use the same first 300/109
source rows so the split sizes stay fixed (see `AGENTS.md`).

## Conventions

- Run scripts from the repository root unless the script says otherwise.
- Python bytecode (`__pycache__/`, `*.pyc`) is generated locally and ignored.
- Output under `reports/` and the large `data/rerank_v2*` trees is generated,
  ignored, and safe to delete.
- Add a new Rust driver as `src/bin/<name>.rs` and declare it in
  `Cargo.toml`; Cargo would auto-discover it, but the explicit entry keeps the
  binary inventory readable.
